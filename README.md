# SELECT — отдельный лендинг каталога

Самостоятельный статический сайт для показа покупателю. Он не импортирует код
CRM или Telegram-бота и переносится/разворачивается отдельно. В каталоге ровно
60 ориентиров: сначала SPORT FIRST (20 пар обуви и 10 вещей для спортсменов),
затем 30 сохранённых лайфстайл-позиций.

Короткая памятка для отдельного Git/static-host находится в
[`DEPLOYMENT_RU.md`](./DEPLOYMENT_RU.md).

Для спортивных позиций показан датированный диапазон открытого рынка РФ, а не
оферта или заявление о наличии. Клиент выбирает вещь, получает ровно один
чистый поисковый запрос «бренд + модель + артикул» и копирует его в бота.
Служебные подписи сайта в запрос не попадают, поэтому бот принимает его сразу,
без предварительного выбора команды. Если задано
публичное имя бота, рядом появляется безопасная ссылка на `https://t.me/...`.

## Быстрый локальный запуск без ключей

Нужен Node.js `^20.19.0` либо `>=22.12.0` (точный диапазон Vite 8).

```bash
npm ci --ignore-scripts
cp .env.example .env.local
npm run dev
```

Откройте адрес, который напечатает Vite (обычно
`http://127.0.0.1:5173`). Пустой `VITE_BOT_USERNAME` — нормальный демо-режим:
выберите карточку и нажмите «Скопировать». Токен Telegram для сайта не нужен.

## Подключение Telegram-бота

В `.env.local` укажите только публичное имя, без `@`:

```dotenv
VITE_BOT_USERNAME=YourBuyerBot
```

Перезапустите dev-сервер. Имя должно начинаться с латинской буквы, содержать
5–32 допустимых символа и заканчиваться на `bot` без учёта регистра.

`BOT_TOKEN`, ключи базы, пароль CRM и любые другие секреты в `VITE_*` помещать
нельзя: Vite встраивает такие значения в публичный JavaScript. `.env.local`
игнорируется Git и Docker-контекстом.

## Проверка перед показом

```bash
npm run check
npm audit --audit-level=moderate
npm audit signatures
```

`npm run check` проверяет хеши и полную WebP-структуру 60 локальных
изображений, границы секретов/деплоя, 19 Vitest-тестов, 9 maintainer-тестов
(6 для защищённого загрузчика и 3 для public boundary) и demo-сборку. Для
полного `check` нужен также `uv`; обычный `npm run dev` Python не использует.
Для ручной проверки:

1. Откройте главную на ширине компьютера и телефона.
2. Переключите все шесть фильтров и выполните поиск `METARISE`.
3. Выберите товар: в поле должен быть только однострочный запрос товара без
   служебных фраз; проверьте кнопку копирования.
4. Без имени бота должна остаться только демо-подсказка; с корректным именем —
   ссылка на `t.me`.
5. В DevTools не должно быть ошибок или запросов к сторонним серверам за
   изображениями.

Демо-сборка и локальный просмотр:

```bash
npm run build
npm run preview
```

## Docker

Для закрытого локального показа используется явно названный demo-target:

```bash
docker build \
  --target demo \
  --build-arg VITE_BOT_USERNAME=YourBuyerBot \
  -t poizon-select-site:demo .
docker run --rm -p 127.0.0.1:8080:8080 poizon-select-site:demo
```

Контейнер собирает проект через `npm ci --ignore-scripts`, затем раздаёт только
готовую статику из Nginx от непривилегированного пользователя. Конфигурация
добавляет CSP, запрет фреймов, MIME-sniffing и лишних browser permissions.
Базовые Node/Nginx-образы закреплены immutable SHA-256 digest.

Для всех 60 project-generated visuals в `sources.json` уже записаны
`rights.status`, generation provenance, hash и дата проверки. Перед каждой
публикацией должны пройти:

```bash
npm run verify:release-rights
npm run verify:release
npm run build:production
docker build --target production -t poizon-select-site:production .
```

Если визуал заменяется официальным product-photo, его нельзя помечать owned
без договора, разрешения владельца или подтверждения товарного API:
release-gate проверяет запись, но не создаёт юридическое право.

## Каталог и изображения

Карточки описаны в `src/catalog/catalog.ts`; браузер загружает изображения
только из `public/catalog`. В `public/catalog/sources.json` для каждого файла
записаны generation method, rights record, размеры, число байт и SHA-256.
Быстрая офлайн-проверка:

```bash
npm run verify:assets
```

`scripts/fetch_catalog_images.py` — отдельный legacy maintainer-инструмент для
проверенного импорта supplier-authorised media. Для него
есть собственные `pyproject.toml` и `uv.lock` с закреплённым Pillow. Он
разрешает только HTTPS/443 и исходный media-host, отключает системные proxy,
проверяет каждый redirect/DNS-адрес, подключается к проверенному IP с TLS для
исходного имени, ограничивает объём и число пикселей до полного декодирования,
а затем пересохраняет изображение в WebP 1200×900 без EXIF/ICC. Инструмент
воспроизводим прямо из корня этого репозитория:

```bash
uv sync --frozen
npm run test:maintainer
uv run --frozen python scripts/fetch_catalog_images.py
```

Файлы являются project-generated visual references, а не официальными
фотографиями товара. Manifest пересобирается командой:

```bash
uv run python scripts/build_catalog_manifest.py
```

Генератор `scripts/generate_catalog_art.py` воспроизводит все 60 карточек —
SPORT FIRST и lifestyle — как единые холодные studio-референсы с товарными
cutout-изображениями там, где это уместно. Публикуемые нормализованные WebP
хранятся в `public/catalog`.

## UI и границы интеграции

Дизайн выполнен локально на React/CSS: белая editorial-витрина, адаптивная
сетка, клавиатурные focus-состояния и уважение `prefers-reduced-motion`.
Использован один небольшой адаптированный компонент Marquee из Magic UI —
аналогичного shadcn подхода «копируем проверяемый компонент в свой код».
Источник, контрольная сумма и MIT-лицензия записаны в
`src/landing/MAGIC_UI_NOTICE.md`; внешнего runtime-пакета Magic UI нет.

Перед реализацией (24 июля 2026) также были просмотрены официальные каталоги
[Motion Primitives](https://motion-primitives.com/),
[Aceternity UI](https://ui.aceternity.com/ai-recommendations) и
[React Bits](https://reactbits.dev/get-started/index). Они подходят для
лендингов, но в эту сборку не добавлены: один проверенный Marquee закрывает
задачу без Motion/Tailwind и без расширения npm supply chain.

Сборка использует относительный Vite base, поэтому готовая папка `dist/`
работает как в корне домена, так и в статическом подпути.

Код папки передаётся без публичной open-source лицензии: до выбора владельцем
условий публикации действует режим «all rights reserved», описанный в
[`LICENSE.md`](./LICENSE.md). Это не меняет MIT-условия отдельно отмеченного
адаптированного Magic UI Marquee.

Сайт не обращается к Poizon и не выполняет расчёт самостоятельно. Попытка
поиска по названию или открытой HTML-ссылке, сверка фото/цены и ручной fallback
остаются ответственностью Telegram-бота и менеджера. Это сохраняет токен и
ключи API только на серверной стороне.

Дополнительная модель угроз и правила публикации описаны в
[`SECURITY.md`](./SECURITY.md).
