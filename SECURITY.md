# Безопасность публичного лендинга

## Граница доверия

`site/` — публичная статическая витрина. Здесь намеренно нет входа в CRM,
серверной сессии, базы, платежей и Telegram-токена. Авторизация нужна CRM, но
не этому публичному каталогу. Единственная настройка сайта —
`VITE_BOT_USERNAME`, публичное имя уже существующего Telegram-бота.

Сайт подготавливает только однострочный поисковый запрос товара; бот принимает
его как прямой ввод. Если пользователь вместо него присылает открытую
HTML-ссылку, бот на сервере извлекает название и сопоставляет его с доступным
источником поставщика. Цена, фото, rate limiting, аудит и ручной fallback
остаются на сервере и у менеджера.

## Реализованные меры

- Имя бота проходит allowlist-проверку, после чего строится только HTTPS-ссылка
  на фиксированный хост `t.me`.
- Запрос очищается от управляющих символов и `<`/`>`; он остаётся
  однострочным plain text, не содержит UI-envelope и не вставляется как HTML.
- Release boundary рекурсивно проверяет разрешённые текстовые файлы `public/`
  и собранного `dist/`, отклоняет неожиданные public-артефакты и
  secret-like assignments/credential URLs/private keys.
- Все 100 основных изображений и 400 галерейных ракурсов локальные. Во время работы сайт не обращается к CDN
  брендов или магазинов.
- CSP запрещает скрипты, стили, изображения, формы, объекты и сетевые
  подключения вне разрешённого минимума; сайт нельзя встроить во фрейм.
- Nginx скрывает версию, отключает MIME-sniffing, реферер и неиспользуемые
  browser permissions.
- Production-контейнер работает не от root, принимает максимум 128 KiB тела
  запроса и не содержит `.env` из рабочей машины.
- npm-пакеты закреплены точными версиями и lock-файлом. Локальный `.npmrc` по
  умолчанию отключает lifecycle-скрипты зависимостей.
- Python maintainer-инструмент имеет отдельный `uv.lock`; загрузчик отключает
  env-proxy, разрешает только порт 443 и исходный media-host, валидирует каждый
  redirect, публичный DNS-адрес и фактический peer до декодирования.
- Один заимствованный UI-компонент хранится в исходниках, имеет зафиксированный
  upstream SHA-256 и приложенный текст MIT-лицензии.

## Цепочка поставки изображений

Текущие 100 визуалов сгенерированы внутри проекта в едином studio-стиле. Все
сохранены в WebP 1200×900 без исходных метаданных. Они не являются
официальными product-photo и не доказывают exact match.

`fetch_catalog_images.py` не является runtime и сохранён только для будущего
supplier-authorised import с HTTPS/DNS/peer/size/MIME validation.

`npm run verify:assets` не использует сеть. Он сверяет ровно 100 основных
файлов и 400 галерейных ракурсов с манифестом, имена, уникальность, полный
RIFF/WebP chunk layout, отсутствие метаданных/анимации/trailing bytes, размеры
1200×900, байты и SHA-256. Это защищает от незаметной подмены после загрузки.

Если визуалы когда-либо заменяются официальными фотографиями, нужно получить
лицензию или использовать медиа поставщика/API и обновить manifest.

## Проверка релиза

```bash
npm ci --ignore-scripts
npm run check
npm run test:maintainer
npm audit --audit-level=moderate
npm audit signatures
npm run verify:release-rights
```

`npm run check` и `npm run build` подходят для локальной проверки. Публичная
сборка дополнительно требует `npm run verify:release` / `npm run
build:production`; без rights/provenance всех 100 файлов она fail-closed.
Docker production использует именно этот gate.

После развёртывания дополнительно проверьте:

```bash
curl -I https://example.com/
curl -I https://example.com/assets/<hashed-file>.js
curl -I https://example.com/catalog/asics-gel-1130-black-pure-silver.webp
```

На каждом ответе должны оставаться CSP, `X-Content-Type-Options: nosniff`,
`X-Frame-Options: DENY`, `Referrer-Policy` и `Permissions-Policy`. Публикуйте
только по HTTPS, не ослабляйте заголовки на CDN и не добавляйте стороннюю
аналитику без отдельной privacy/security оценки.

## Что не решает статический сайт

- Он не подтверждает наличие или цену товара.
- Он не защищает серверный бот: бот должен отдельно проверять URL против SSRF,
  ограничивать редиректы/размеры/таймауты, экранировать Telegram-разметку и
  применять rate limits.
- Он не предоставляет авторизацию CRM. CRM должна жить на отдельном origin или
  за отдельным reverse-proxy route с серверной аутентификацией, secure cookies,
  CSRF-защитой и журналом действий.

Если в публичную сборку случайно попал секрет, считайте его раскрытым: сначала
отзовите/замените секрет, затем удалите артефакт и пересоберите сайт.
