## Результат

- На точном указателе увеличивается только карточка под курсором, коэффициент 1.025. Панель размеров находится поверх следующего ряда. Размеры сетки, страницы и соседних карточек сохраняются.
- Клавиатура открывает панель без увеличения; reduced motion отключает масштабирование и переход; touch открывает карточку обычным нажатием.
- Все актуальные доступные размеры с ценами представлены в прокручиваемой панели карточки. В карточке товара показаны все размерные ячейки и цены актуальных SKU. Исторические суммы и даты скрыты; неизвестные и просроченные предложения не получают разрешения на заказ.
- Выбор актуального размера для просмотра цены не требует checkout_confirmed. Добавление в корзину по-прежнему требует отдельного подтверждённого SKU и разрешения сервера.
- Расцветки появляются только по явному взаимному catalog_colorways с точной идентичностью товара и актуальным подтверждением наличия. Переход ведёт на собственный URL товара, с его галереей, размерами и ценами. Названия товаров не используются для вычисления родства.
- Число товаров берётся из catalog_count; состав принимается только при полном покрытии статусов и уникальности товаров. Поддерживается добавление новых проверенных расцветок сверх исходных 200.
- При истечении отдельного SKU остальные актуальные предложения сохраняются, минимум пересчитывается по оставшимся серверным значениям. Серверный срок снимка и исходные временные метки не продлеваются. Таймер срабатывает и при зависшем обновлении. Просроченный выбранный размер сбрасывается в ProductSheet и ProductDetailPage.

## Дополнение: счётчик при первоначальной загрузке

Фактический first-paint на 4173 показывал «100 товаров» и «Осталось 76» около 484 мс до получения ответа 209. Счётчик использовал размер встроенной подборки, хотя состояние API было loading.

Ограниченная правка меняет только подписи: при первоначальном loading — «Загружаем каталог…» с `aria-busy=true`, внизу — «Каталог загружается». После первого ответа возвращаются прежний счётчик отфильтрованных товаров и подпись остатка; `aria-busy=false`. Карточки и механика пагинации сохраняются. Ошибка или неполный состав по-прежнему оставляют встроенную подборку, её числовой счётчик и существующее сообщение состояния. Обновление после успешной загрузки не переводит состояние обратно в loading и не скрывает подтверждённый счётчик.

Проверки дополнения: 90 затронутых существующих тестов и четыре новых сценария (pending, complete209, failed100, incomplete100), lint и build. На фактическом API через dev4183, без fixture/interception, first-paint переходит «Загружаем каталог…» → «209 товаров, показано 24» без промежуточного 100. Артефакты: `tmp/catalog-initial-count/before.json` и `after-4183.json`. Родитель пересобирает 4173 после применения отдельного follow-up-коммита.

## Дополнение: подключение media foundation

Адаптер использует результат `getSupplierCatalogMedia(product)` для image, fallbackImage и всех элементов gallery. Полный набор требует пяти утверждённых ракурсов в установленном порядке; ошибка productRef, отсутствующий кадр или незавершённая проверка сохраняют исходную галерею. В resolver и verifier дополнительно проверяется точное имя `/catalog/supplier/<slug>-<position>.webp`, чтобы имя файла соответствовало идентичности и позиции кадра из контракта.

Фотографии не добавлялись: manifest содержит 176 точных идентичностей и ноль активных кадров. `verify:assets` допускает такой этап разработки и явно сообщает `STANDARDIZATION INCOMPLETE`; `verify:media-supplier` с `--require-complete` завершается ошибкой при 0/176 полных комплектов. Успех проверки разработки не означает готовность медиарелиза.

Старый bundle guard запрещал любые строки `/catalog/`, включая новый контракт. Согласование сохраняет этот запрет для остальных путей: разрешены только служебный префикс валидатора `/catalog/supplier/` и точные имена из supplier manifest, присутствующие в dist. Необъявленные пути, чужие имена, traversal и абсолютные legacy-пути по-прежнему отклоняются. Служебный префикс не возвращается адаптером как изображение; пути кадров проходят через существующий `resolveAssetUrl`. Отдельные UI-тесты проверяют фактические src первого/третьего кадра карточки, всех пяти миниатюр и переключение пятого кадра на вложенном URL товара.

Сборка интеграции выполняется отдельно в `tmp/media-integration-build/dist`: проверки assets/boundaries, TypeScript, Vite с отдельным outDir и текущий `verify_dist_portability.mjs`, скопированный вместе с `catalog_bundle_urls.mjs` и supplier manifest рядом с этим тестовым dist. Работающий `dist` не перезаписывается, процесс 4173 не перезапускается. Родитель собирает итоговую версию после приёма коммита.

Продукционный деплой не выполнялся. API/CRM/порт 4173 не перезапускались. Заказы, платежи и сообщения не отправлялись.
